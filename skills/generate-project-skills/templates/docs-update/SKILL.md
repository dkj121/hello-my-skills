# Docs Update

Two steps, in order: maintain the catalog, then update the documents it indexes.

## Self-maintenance — run this first

This skill is a living artifact of this codebase. Before starting:

1. Verify the document locations below still match reality.
2. If new documentation areas appeared (a `docs/` subtree, an ADR folder), record them in this SKILL.md first (both copies: `.claude/skills/docs-update/` and `.agents/skills/docs-update/`), then catalog them.

## Project facts

- Documentation locations: {{DOC_LOCATIONS}} — plus the repo root (ARCHITECTURE.md, SPEC.md, WORKFLOW.md, HANDOFF.md, INDEX.md)

## Step 1 — INDEX.md, the catalog

INDEX.md lives at the repository root. Maintain one table covering every document in the repo:

| Document | Path | Contents | Maintained by | Last updated |
| --- | --- | --- | --- | --- |

- Root docs generated by skills (ARCHITECTURE.md, SPEC.md, WORKFLOW.md): "Maintained by" names the owning skill (to-docs / implement). HANDOFF.md is owned by the handoff skill — catalog it, never edit it.
- Handwritten docs (README, docs/**, ADRs, CONTRIBUTING): "Maintained by" is human — update their row when they change, but don't rewrite their content in step 2 unless the change directly affects them.
- Add rows for new documents; drop rows for deleted ones; refresh "Last updated" only for documents actually touched. If INDEX.md doesn't exist yet, create it and populate it fully.

## Step 2 — Update affected documents

From the catalog plus the current change context (conversation, recent diffs):

- Root docs first: ARCHITECTURE.md (did structure change?), SPEC.md (did goals or scope change?), WORKFLOW.md (did commands or process change?).
- Then any other document the changes affect — a README section referencing a renamed command, an API doc for a changed endpoint. Match each document's existing tone and language.
- Don't rewrite documents the changes don't touch. Don't create documents nobody asked for.

## Output

Report catalog changes and per-document edits — one line each.
